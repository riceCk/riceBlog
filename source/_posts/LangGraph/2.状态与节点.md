# 状态
- Schema
- reducer

**1.Schema**
Schema用来做状态的结构约束，统一规定：

* 这个图全局状态
* 有哪些字段
* 字段类型是哪些
* 那些是必须的

```bash
import * as z from "zod";
const Schema = z.object({
  messages: z.array(z.custom<BaseMessage>()),
  llmCalls: z.number().optional(),
});
```

* 默认情况下，图的输入Schema = 输出 Schema
* 可以手动分别指定 input Schema 和 output Schema

```bash
const inputSchema = z.object({
  query: z.string()
})
const outputSchema = z.object({
  query: z.string(),
  answer: z.string(),
  metadta: z.object({
    model: z.string(),
    tokens: z.number(),
    duration: z.number()
  })
})
# 实例化
new StateGraph({
  input: inputSchema,
  output: outputSchema
})
```

**2.reducer**
状态合并器，reducer决定这些更新如何和旧的状态合并，默认是覆盖
工作原则：
1. 节点只需返回“要更新的那一小块”，不用把整份 state 再抄一遍。
2. 如果没为某个 key 指定 reducer，就按默认策略：直接覆盖，后来的值把前面的值盖掉。
3. 每个 key 可以有各自的合并方式，例如指定 number 怎么合？array 怎么合？


示例：要更新的那一小块，不用把整份 state 再抄一遍
```bash
# 节点1
async function node1() {
  return {
    count: 1,
  };
}
# 节点2
async function node2(state: TState) {
  return {
    logs: [`第一条log，count=${state.count}`],
  };
}
# 节点3
async function node3() {
  return {
    status: "完成",
  };
}
# 节点4
async function node4() {
  return {
    count: 200,
  };
}
# 节点5
async function node5(state: TState) {
  return {
    logs: [`第二条log，count=${state.count}`],
  };
}
# { count: 200, logs: [ '第二条log，count=200' ], status: '完成' }
```

示例2：每个 key 可以有各自的合并方式，例如指定 number 怎么合？array 怎么合？

```bash
const Schema = z.object({
  count: z.number().register(registry, {
    reducer: {
      # 这里因为指定了reducer，因此在进行状态合并的时候
      # 不再是新的状态去覆盖旧的状态，而是新旧状态相加
      fn: (oldVal, newVal) => oldVal + newVal,
    },
    default: () => 0,
  }),
  logs: z.array(z.string()).register(registry, {
    reducer: {
      # 新旧状态拼接到一起，而非覆盖
      fn: (oldVal, incoming) => oldVal.concat(incoming), # 拼接数组
    },
    default: () => [] as string[], # 没有旧值时，用空数组作为初始值
  }),
  status: z.string().optional(),
});
```


**3. messages**
把“上下文对话”保存在 `state.messages` 里，供后续节点读取与追加。这里官方推荐 `MessagesZodMeta`
```bash
import { StateGraph, MessagesZodMeta } from "@langchain/langgraph";
import { registry } from "@langchain/langgraph/zod";
# import * as z from "zod";
import { z } from "zod/v4";
import { BaseMessage } from "@langchain/core/messages";

const State = z.object({
  messages: z
    .array(z.custom<BaseMessage>()) # 用 BaseMessage 数组承载对话
    .register(registry, MessagesZodMeta), # 通过 MessagesZodMeta 绑定“按 id 合并/覆盖”的 reducer + 序列化逻辑

  # 还可以放其它业务字段
  documents: z.array(z.string()).optional(),
});

const graph = new StateGraph(State);
```

这里的 reducer 不是 concat，而是 `MessagesZodMeta` 内部的智能 reducer，它的特性：

- 有 `id` 的消息：覆盖

  ```ts
  return { messages: [ new HumanMessage({ id: "m-123", content: "修正内容" }) ] }
  ```

  不会 append，而是覆盖同 id 的消息

- 没有 `id` 的消息：追加

  ```ts
  return { messages: [ new AIMessage("hi") ] }
  ```

  会追加到 messages 末尾

能够达到双模式。


示例
```bash
import { StateGraph, START, END, MessagesZodMeta } from "@langchain/langgraph";
import { registry } from "@langchain/langgraph/zod";
import {
  BaseMessage,
  HumanMessage,
  AIMessage,
} from "@langchain/core/messages";
# import * as z from "zod";
import { z } from "zod/v4";
# 定义Schema
const Schema = z.object({
  messages: z
    .array(z.custom<BaseMessage>())
    .register(registry, MessagesZodMeta),
});

# type TState = z.infer<typeof Schema>;

async function node1() {
  const msg = new HumanMessage({
    content: "你好，langgraph",
  });

  return {
    messages: [msg], # 追加
  };
}

async function node2() {
  const msg = new AIMessage({
    content: "你好，langgraph22222",
  });

  return {
    messages: [msg], # 追加
  };
}

async function node3() {
  const msg = new HumanMessage({
    id: "m-123",
    content: "修正用户消息",
  });

  return {
    messages: [msg], # 更新 id 为 m-123 的消息内容
  };
}

async function node4() {
  const msg = new AIMessage({
    id: "m-456",
    content: "修正AI回复的消息",
  });

  return {
    messages: [msg], # 更新 id 为 m-456 的消息内容
  };
}

const app = new StateGraph(Schema)
  .addNode("node1", node1)
  .addNode("node2", node2)
  .addNode("node3", node3)
  .addNode("node4", node4)
  .addEdge(START, "node1")
  .addEdge("node1", "node2")
  .addEdge("node2", "node3")
  .addEdge("node3", "node4")
  .addEdge("node4", END)
  .compile();

const result = await app.invoke({
  # 一开始有两条信息
  messages: [
    new HumanMessage({ id: "m-123", content: "这是原始的用户消息" }),
    new AIMessage({ id: "m-456", content: "这是原始的AI回复消息" }),
  ],
});
console.log(result);
```

# 节点

## 节点参数
graph.addNode("节点名称", 节点函数);

```bash
graph.addNode("myNode", (state, config) => {
  console.log("In node: ", config?.configurable?.user_id);
  return { results: `Hello, ${state.input}!` };
})
addNode("otherNode", (state) => {
  return state;
})

## 默认节点名

如果不书写节点名称，会自动取**函数名作为节点名**。例如：

```bash
function myNode(state) {
  return { ... };
}

graph.addNode(myNode);
# graph.addNode("myNode", myNode);
```

## 节点缓存机制

某一些节点函数计算昂贵，可以选择将其缓存起来，这样下次有相同的输入时不用再重新执行节点，而是直接返回缓存结果。

**1. `compile()` 编译图的时候，启用缓存**

```ts
graph.compile({ cache: new InMemoryCache() });
```

表示整个图都使用内存缓存。

也可以换成 Redis、file、database 等。

缓存策略有两种：

1. ttl：缓存有效时长（秒），决定“缓存多久过期”，适用于想让缓存自动失效时。
2. keyFunc：自定义缓存 key，决定“什么输入算同一个缓存”，适用于**想精细控制缓存命中逻辑时**。
   - LangGraph 在执行流程中有多个“检查缓存”的时机，而每个时机的 state 结构不同（有时已 reduce、有时未 reduce）
   - 因此 cachePolicy 的 keyFunc 会发生在 “reduce 前” 或 “reduce 后” 的不同位置，有可能拿到：
     - 单一 state
     - reducer 尚未处理的 state 数组


```bash
const app = new StateGraph(Schema)
  .addNode(
    "node1",
    async (state: TState) => {
      # 演示一个耗时的操作
      console.log("这是一个耗时的操作...");
      await new Promise((r) => setTimeout(r, 5000));
      return {
        result: `${state.query}对应答案`,
      };
    },
    {
      cachePolicy: {
        keyFunc: (state: any) => {
          const s = Array.isArray(state) ? state[state.length - 1] : state;
          console.log(s?.userId, "state=============");
          return s?.userId;
        },
        # ttl: 10, # 缓存10秒，单位是秒
      },
    },
  )
  .addEdge(START, "node1")
  .addEdge("node1", END)
  .compile({
    cache: new InMemoryCache(), # 开启缓存
  });
```
