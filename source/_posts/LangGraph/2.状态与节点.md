# 🧩 状态

状态是整张图共享的那份数据。两件事要先定：字段长什么样（Schema），以及节点返回的一小块怎么并回去（reducer）。

## Schema

Schema 规定全局状态有哪些字段、各是什么类型、哪些必填。

```js
import * as z from "zod";

const Schema = z.object({
  messages: z.array(z.custom()),
  llmCalls: z.number().optional(),
});
```

默认情况下，图的输入 Schema 和输出 Schema 是同一份。也可以分开写：调用时只收 `query`，跑完后再带上 `answer` 和 `metadata`。

```js
const inputSchema = z.object({
  query: z.string(),
});
const outputSchema = z.object({
  query: z.string(),
  answer: z.string(),
  metadata: z.object({
    model: z.string(),
    tokens: z.number(),
    duration: z.number(),
  }),
});

new StateGraph({
  input: inputSchema,
  output: outputSchema,
});
```

## reducer

节点不用把整份 state 抄一遍，只返回要改的那几项。没给某个字段指定 reducer 时，新值直接覆盖旧值。每个字段可以有自己的合并方式：数字相加、数组拼接。

下面五个节点各自只改一块。`count` 没有 reducer，节点 4 的 `200` 会盖掉节点 1 的 `1`。`logs` 如果也没 reducer，节点 5 同样会盖掉节点 2 留下的那条。

```js
async function node1() {
  return { count: 1 };
}
async function node2(state) {
  return { logs: [`第一条 log，count=${state.count}`] };
}
async function node3() {
  return { status: "完成" };
}
async function node4() {
  return { count: 200 };
}
async function node5(state) {
  return { logs: [`第二条 log，count=${state.count}`] };
}
// 默认覆盖后大致是：
// { count: 200, logs: ["第二条 log，count=200"], status: "完成" }
```

要改成「数字累加、日志追加」，给字段登记 reducer：

```js
const Schema = z.object({
  count: z.number().register(registry, {
    reducer: {
      fn: (oldVal, newVal) => oldVal + newVal,
    },
    default: () => 0,
  }),
  logs: z.array(z.string()).register(registry, {
    reducer: {
      fn: (oldVal, incoming) => oldVal.concat(incoming),
    },
    default: () => [],
  }),
  status: z.string().optional(),
});
```

## messages

对话放在 `state.messages`。官方推荐用 `MessagesZodMeta`，它自带的 reducer 不是简单拼接：

- 新消息带了已有的 `id`：覆盖那一条
- 没有 `id`：追加到末尾

```js
import { StateGraph, MessagesZodMeta } from "@langchain/langgraph";
import { registry } from "@langchain/langgraph/zod";
import { z } from "zod/v4";
import { BaseMessage } from "@langchain/core/messages";

const State = z.object({
  messages: z
    .array(z.custom())
    .register(registry, MessagesZodMeta),
  documents: z.array(z.string()).optional(),
});
```

```js
return { messages: [new HumanMessage({ id: "m-123", content: "修正内容" })] }; // 覆盖同 id
return { messages: [new AIMessage("hi")] }; // 追加
```

四个节点串起来时：没 id 的会追加，带 `m-123`、`m-456` 的会改掉一开始放进去的那两条。

```js
import { StateGraph, START, END, MessagesZodMeta } from "@langchain/langgraph";
import { registry } from "@langchain/langgraph/zod";
import { HumanMessage, AIMessage } from "@langchain/core/messages";
import { z } from "zod/v4";

const Schema = z.object({
  messages: z.array(z.custom()).register(registry, MessagesZodMeta),
});

async function node1() {
  return { messages: [new HumanMessage({ content: "你好，langgraph" })] };
}
async function node2() {
  return { messages: [new AIMessage({ content: "你好，langgraph22222" })] };
}
async function node3() {
  return { messages: [new HumanMessage({ id: "m-123", content: "修正用户消息" })] };
}
async function node4() {
  return { messages: [new AIMessage({ id: "m-456", content: "修正 AI 回复" })] };
}

const app = new StateGraph(Schema)
  .addNode("node1", node1)
  .addNode("node2", node2)
  .addNode("node3", node3)
  .addNode("node4", node4)
  .addEdge(START, "node1")
  .addEdge("node1", "node2")
  .addEdge("node2", "node3")
  .addEdge("node3", "node4")
  .addEdge("node4", END)
  .compile();

const result = await app.invoke({
  messages: [
    new HumanMessage({ id: "m-123", content: "这是原始的用户消息" }),
    new AIMessage({ id: "m-456", content: "这是原始的 AI 回复" }),
  ],
});
```

# 节点

```js
graph.addNode("节点名称", 节点函数);
```

节点函数收到当前 `state`，可选再收 `config`（里面有 `configurable`，例如用户 id）。返回值是要合并进状态的那一块。

```js
graph.addNode("myNode", (state, config) => {
  console.log("In node:", config?.configurable?.user_id);
  return { results: `Hello, ${state.input}!` };
});
```

不写名字时，用函数名当节点名：`graph.addNode(myNode)` 等价于 `graph.addNode("myNode", myNode)`。

`START` 是入口，`END` 是结束。它们不是你写的函数，只用来连边。

## 缓存

某个节点很贵时，可以按输入缓存结果。编译时打开缓存，节点上再写 `cachePolicy`。

```js
graph.compile({ cache: new InMemoryCache() });
```

内存缓存可以换成 Redis、文件或数据库。策略有两处可调：

- `ttl`：多少秒后过期
- `keyFunc`：什么输入算同一次。检查缓存时，state 有时还没 reduce、有时已经 reduce，所以 `keyFunc` 可能拿到单个对象，也可能拿到数组。数组时取最后一项。

```js
const app = new StateGraph(Schema)
  .addNode(
    "node1",
    async (state) => {
      console.log("这是一个耗时的操作...");
      await new Promise((r) => setTimeout(r, 5000));
      return { result: `${state.query}对应答案` };
    },
    {
      cachePolicy: {
        keyFunc: (state) => {
          const s = Array.isArray(state) ? state[state.length - 1] : state;
          return s?.userId;
        },
        // ttl: 10,
      },
    },
  )
  .addEdge(START, "node1")
  .addEdge("node1", END)
  .compile({
    cache: new InMemoryCache(),
  });
```
