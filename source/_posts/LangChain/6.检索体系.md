
# 文本切割器
最通用的使用`RecursiveCharacterTextSplitter`切割
快速上手
```bash
import { RecursiveCharacterTextSplitter } from "@langchain/classic/text_splitter";
import { TextLoader } from "@langchain/classic/document_loaders/fs/text";

const loader = new TextLoader("./data/test.txt");
const docs = await loader.load();
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 64, 
  chunkOverlap: 10, 
});
const result = await splitter.splitDocuments(docs);
console.log(result);
```
* chunkSize: 每块的最大长度
* chunkOverlap: 块之间的重叠长度

## 其他不同的切割器
| Splitter名称 | 适用文档类型 | 切分策略说明 |
|------|----------|------|
|RecursiveCharacterTextSplitter|普通文本（小说、说明）| 默认最常用，按字符层级递进切分|
|MarkdownTextSplitter|Markdown|根据标题层级（#、##等）结构来切|
|TokenTextSplitter|精确控制token清空|按token数切分，不考虑语义|
|CharacterTextSplitter|非结构文本|纯字符切，简单粗暴|

快速上手
```bash
import { TextLoader } from "@langchain/classic/document_loaders/fs/text";
import { MarkdownTextSplitter } from "@langchain/classic/text_splitter";
 const loader = new TextLoader("./data/1111.md");
const docs = await loader.load();
const splitter = new MarkdownTextSplitter({
  chunkSize: 64, 
  chunkOverlap: 10, 
});
const result = await splitter.splitDocuments(docs);
console.log(result);
```

**切割代码**
`RecursiveCharacterTextSplitter.fromLanguage('js', {...})` 会根据指定语言注入专门的分隔符表，优先按照函数或类定义等结构分隔（`function`/`class`等关键字周围），再按照语句结束符（`;`）分隔，再按照换行符空格符等兜底分隔
```bash
import { TextLoader } from "@langchain/classic/document_loaders/fs/text";
import { RecursiveCharacterTextSplitter } from "@langchain/classic/text_splitter";

const loader = new TextLoader("./data/browser.js");
const docs = await loader.load();
const splitter = RecursiveCharacterTextSplitter.fromLanguage("js", {
  chunkSize: 500, 
  chunkOverlap: 0, 
});
const result = await splitter.splitDocuments(docs);
console.log(result);
``` 

# 嵌入处理
嵌入处理，又称为向量化操作，核心就是将文本转为向量形式，从而为下一步做数据运算准备。

依赖专门的嵌入处理模型。比如：
```bash
import {OpentAIEmbeddings} from '@langchain/openai';
const embeddings = new OpentAIEmbeddings({
  apiKey: '注册apiKey',
  model: 'text-embedding-3-largen', # OpenAI 官方提供的专门用于做嵌入的模型
})
const vectors = await embeddings.embedDucuments(documents.map(doc => doc.pageContent))
```

快速上手1.1代码
通过`nomic-embed-text`模型进行嵌入式处理
```bash
# 文本读取
const loader = new TextLoader("./data/test.txt");
const docs = await loader.load();
# 文本切割
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 64,
  chunkOverlap: 0,
});
const splittedDocs = await splitter.splitDocuments(docs);
# 嵌入处理
async function getEmbedding(text) {
  const res = await fetch("http://localhost:11434/api/embeddings", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      model: "nomic-embed-text",
      prompt: text,
    }),
  });
  const result = await res.json();
  return result.embedding;
}
const results = [];
for (const doc of splittedDocs) {
  const embedding = await getEmbedding(doc.pageContent);
  results.push( { ...doc, embedding });
}
console.log(results);
```
不过目前例子，进行嵌入式属于串行嵌入，花费时间比较长，需要用到并发的嵌入操作

## 自定义嵌入类
要实现并发的嵌入操作，需要**自定义个嵌入类**
Embeddings是LangChain中抽象出来的**嵌入操作类**，不同厂商的向量模型，都通过继承改基类暴露统一方法，从而能在向量库、检索器等组件互换使用
基类提供两组最核心的方法：
* `embedDocuments(texts: string[]) => Promise<number[][]>`: 批量嵌入用于索引的文本（返回二维向量）
* `embedQuery(text:string) => Promise<number[]>`: 为查询文本生成向量（返回一维向量）

使用并发方法：runWithConcurrency
```bash
/**
 *
 * @param {*} items 要处理的任务列表
 * @param {*} worker 处理单个任务的异步函数
 * @param {*} maxConcurrency 最大并发量
 */
export async function runWithConcurrency(items, worker, maxConcurrency) {
  let i = 0; # 指向当前任务
  const workers = []; # 用于存储promise
  # 启动工人开始干活
  async function spawn() {
    while (i < items.length) {
      const idx = i++;
      await worker(items[idx], idx);
    }
  }
  # 可将最大并发数看作n个工人
  const n = Math.max(1, Math.min(maxConcurrency, items.length));
  for (let i = 0; i < n; i++) {
    workers.push(spawn());
  }
  # 等待所以任务执行完
  await Promise.allSettled(workers);
}
```

实现自定义并发类，这里之所以引入Embeddings基类，类似做个接口的规范，软件工程里是一种常见的设计模式，叫做“**接口实现**”。通过继承一个抽象基类，你向框架（LangChain）声明：“我实现了你要求的嵌入能力，请把我当作标准组件来使用。” 
```bash
import { Embeddings } from "@langchain/core/embeddings";
import { runWithConcurrency } from "./concurrency.js";

export class NomicEmbeddings extends Embeddings {
  constructor(concurrency = 3) {
    super();
    this.model = "nomic-embed-text";
    this.apiUrl = "http://localhost:11434/api/embeddings";
    this.concurrency = concurrency;
  }

  /**
   * 对单个文本做嵌入式操作，这是一个内部方法
   * @param {*} text 单个文本
   */
  async _fetchEmbedding(text) {
    const res = await fetch(this.apiUrl, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        model: this.model,
        prompt: text,
      }),
    });
    const result = await res.json();
    return result.embedding;
  }

  /**
   * 对单个文本做嵌入操作
   * @param {*} text
   */
  async embedQuery(text) {
    return await this._fetchEmbedding(text);
  }

  /**
   * 对一组文本做嵌入
   * @param {*} doucments
   */
  async embedDocuments(documents) {
    const results = Array.from({ length: documents.length }); // 存放结果的数组
    await runWithConcurrency(
      documents,
      async (text, idx) => {
        try {
          results[idx] = await this._fetchEmbedding(text);
        } catch (err) {
          results[idx] = err;
        }
      },
      this.concurrency,
    );
    return results;
  }
}
```
使用**NomicEmbeddings**方法
```bash
# 文本读取
const loader = new TextLoader("./data/test.txt");
const docs = await loader.load();
# 文本切割
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 300,
  chunkOverlap: 0,
});
const splittedDocs = await splitter.splitDocuments(docs);
const texts = splittedDocs.map((doc) => doc.pageContent)

const embeddings = new NomicEmbeddings(5);
const res = await embeddings.embedDocuments(
  splittedDocs.map((doc) => doc.pageContent),
);
console.log(res);
```

# 存储向量数据库
* 内存型
* 本地自托管
* 云托管

LangChain内置了MemoryVectorStore,这是一个内存型向量库，用于将文档向量存储到内存中，适合本地调试、快速演练，零依赖、即插即用

**添加文档内存**
添加文档可以调用`MemoryVectorStore`实例的`addDocuments`方法，该方法接受一个数组，数组里面每一项是Document实例对象，之后自动调用embeddings.embedDoucuments生成向量并存入内存
```bash
import { MemoryVectorStore } from "@langchain/classic/vectorstores/memory";
import { NomicEmbeddings } from "./utils/embed.js";
import { TextLoader } from "@langchain/classic/document_loaders/fs/text";
import { RecursiveCharacterTextSplitter } from "@langchain/classic/text_splitter";

const loader = new TextLoader("data/test.txt");
const docs = await loader.load();

const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 64,
  chunkOverlap: 0,
});

const splitterDocs = await splitter.splitDocuments(docs);
const embeddings = new NomicEmbeddings(4);

const store = new MemoryVectorStore(embeddings);

await store.addDocuments(splitterDocs);

# 存到内存里
console.log(store.memoryVectors);
```

**检索操作**
`store.asRetriever(2)`是一个简写，等价于`store.asRetriever({k: 2})`，表达创建一个检索器，每次查询前两条最相似的`Document`。返回值是个`VectorStoreReteriver`
```bash
const retriever = store.asRetriever(2);
const res = await retriever.invoke("Agent评测思路");
```

**配置对象支持如下的参数：**
```bash
const retriever = store.asRetriever({
  k: 2,
  searchType: "mmr",
  searchKwargs: { fetchK: 20, lambda: 0.5 },
  filter: (doc) => doc.metadata?.source?.endsWith("data/test.txt"),
  tags: ["demo", "kong"],
  metadata: { lesson: "RAG-intro" },
  verbose: true,
});
```
* k: 每次查询返回的文档条数：不填默认`4`.
* searchType: 检索策略：
  * "similarity"（默认）：按向量相似度排序返回前k条；
  * "mmr": 最大边际相关性，在相关性与多样性之间折中。
* searchKwargs: MMR的细化参数，仅当`searchType: 'mmr'`时生效
  * fetchK: 先抓取的候选集合规模（越大，MMR可选空间越大）
  * lambda：0~1的权衡系数；0 更多偏向多样性、1更偏向相关性
* filter: 用于预筛选候选文档，返回`true`的文档才参与检索
* callbacks: 检索过程中的回调钩子（开始/结束/错误等），与LangChain的客观性机制对接
* tags：给该检索器打标签，便于在日志/跟踪里区分。
* metadata: 附加的上下文信息，会随运行一起记录，便于审计与调试
* verbose: 是否开启详情日志，默认false

## MultiQueryRetriever
MultiQueryRetriever是LangChain中一个工具类，作用是**用一个大模型**把用户问题改写成多种表述（多视角查询），**对每个改写分别检索**，然后合并去重结果，缓解**单一措辞**导致召回不足的问题

快速上手

```bash
const loader = new TextLoader("data/test.txt");
const docs = await loader.load();
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 64,
  chunkOverlap: 0,
});
const splittedDocs = await splitter.splitDocuments(docs);
const embeddings = new NomicEmbeddings(3);
const store = new MemoryVectorStore(embeddings);
await store.addDocuments(splittedDocs);
const retriever = store.asRetriever(2);
const llm = new ChatOllama({
  model: "llama3",
  temperature: 0.7,
});
const r = MultiQueryRetriever.fromLLM({
  llm, # 使用什么模型改写提示词
  retriever, # 基础检索器
  queryCount: 3, # 要扩充的数据量
});
const res = await r.invoke("Agent评测思路");
```
这里asRetriever检索器k指定的2，理论上应该是两条结果，queryCount扩散3条，所以理论上是2*3=6结果（对每个改写分别检索），不过合并去重结果，会4条数据

## ContextualCompressionRetriever
该类工具类用于在检索出原始相关文档之后，进一步压缩内容过滤掉不相关的部分，返回更简洁、更聚焦于问题的文档片段
```bash
const llm = new ChatOllama({
  model: "llama3",
  temperature: 0.7,
});

# 创建了一个压缩器
const extractor = LLMChainExtractor.fromLLM(llm);
# 构建一段文档
const docs = [
  new Document({
    pageContent: `孔乙己走到酒店，说“要一碟茴香豆”。茴香豆常作为下酒小菜，价格便宜，常见于短衣帮和穿长衫的顾客点酒时。`,
  }),
  new Document({
    pageContent: `另一个段落：今天的天气很好，阳光明媚。`,
  }),
  new Document({
    pageContent: `游泳池边上，游过一群小黄鸭`,
  }),
  new Document({
    pageContent: `茴香豆可以拿来泡茶，上次我就看到有一个大婶儿拿茴香豆来泡茶`,
  }),
];
const query = "茴香豆的作用";
const res = await extractor.compressDocuments(docs, query);
console.log(res); # 压缩内容过滤掉不相关的部分
```

## ScoreThresholdRetriever
是基于相似度“阈值过滤”的检索器：它在向量库中检索时，只返回**相似度分数不低于**你设定的阈值的文档，该类继承自`VectorStoreRetriever`，提供`invocke()`等可运行接口方法
使用实例：
```bash
const r = ScoreThresholdRetriever.fromVectorStore(store, {
  minSimilarityScore: 0.7,
});
const res = await r.invoke("茴香豆是做什么用的");
console.log(res);
```
除了该配置之外，还支持下面配置：
* `kIncrement: number `(默认10)每次追加抓取的候选数量递增，用于在需要时扩大候选集，按照阈值过滤
* `maxK:number(默认100)` 抓取候选的上限，避免无限扩大搜索范围
* `searchType: 'similarity' | 'mmr'`: 可选设为`mmr`做多样性与相关性的权衡：默认'similarity'
* 其余通用项：`filter`,`verbose`,`callbacks`,`tags`,`metadata`
