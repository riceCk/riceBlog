# 🔍 检索体系

检索分三层：把文档切开，变成向量，放进向量库再按相似度找回来。

```text
数据：Document → TextLoader → TextSplitter
向量：Embeddings → MemoryVectorStore
检索：asRetriever(k)
再加工：多问法 / 压缩 / 按分数过滤
```

# 文本切割

最常用 `RecursiveCharacterTextSplitter`。`chunkSize` 是一块的最大长度，`chunkOverlap` 是相邻两块重叠多少，避免一句话被切在边界上。

```js
import { RecursiveCharacterTextSplitter } from "@langchain/classic/text_splitter";
import { TextLoader } from "@langchain/classic/document_loaders/fs/text";

const docs = await new TextLoader("./data/test.txt").load();
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 64,
  chunkOverlap: 10,
});
const result = await splitter.splitDocuments(docs);
```

| Splitter | 适合 | 怎么切 |
|------|------|------|
| `RecursiveCharacterTextSplitter` | 普通文本 | 先按段落、再按句子、再按字符，一层层退 |
| `MarkdownTextSplitter` | Markdown | 按 `#`、`##` 这种标题切 |
| `TokenTextSplitter` | 要卡 token 预算 | 按 token 数切，不看语义 |
| `CharacterTextSplitter` | 很随意的文本 | 只按字符切 |

Markdown 换一个类，参数一样：

```js
import { MarkdownTextSplitter } from "@langchain/classic/text_splitter";

const splitter = new MarkdownTextSplitter({
  chunkSize: 64,
  chunkOverlap: 10,
});
```

切代码时用 `fromLanguage("js")`。它会优先在 `function`、`class` 附近断开，其次是分号，最后才是换行和空格。

```js
const splitter = RecursiveCharacterTextSplitter.fromLanguage("js", {
  chunkSize: 500,
  chunkOverlap: 0,
});
```

# 嵌入

嵌入就是把文本变成向量，后面才能算相近程度。厂商不同，类不同，方法是同一套：

- `embedDocuments(texts)`：一批文档，返回二维数组，建索引时用
- `embedQuery(text)`：一个问题，返回一条向量，查询时用

```js
import { OpenAIEmbeddings } from "@langchain/openai";

const embeddings = new OpenAIEmbeddings({
  apiKey: "注册的 apiKey",
  model: "text-embedding-3-large",
});
const vectors = await embeddings.embedDocuments(documents.map((doc) => doc.pageContent));
```

本地用 Ollama 的 `nomic-embed-text`。下面是串行版本，文档一多会慢：

```js
async function getEmbedding(text) {
  const res = await fetch("http://localhost:11434/api/embeddings", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      model: "nomic-embed-text",
      prompt: text,
    }),
  });
  const result = await res.json();
  return result.embedding;
}

const results = [];
for (const doc of splittedDocs) {
  const embedding = await getEmbedding(doc.pageContent);
  results.push({ ...doc, embedding });
}
```

## 自己写一个嵌入类

继承 `Embeddings`，是在告诉 LangChain：这两个方法我实现了，请把我当成标准组件。向量库和检索器就可以直接用。

并发靠一个工人池：同时最多跑 `maxConcurrency` 个请求，谁先完成谁领下一条。

```js
export async function runWithConcurrency(items, worker, maxConcurrency) {
  let i = 0;
  const workers = [];

  async function spawn() {
    while (i < items.length) {
      const idx = i++;
      await worker(items[idx], idx);
    }
  }

  const n = Math.max(1, Math.min(maxConcurrency, items.length));
  for (let k = 0; k < n; k++) workers.push(spawn());
  await Promise.allSettled(workers);
}
```

```js
import { Embeddings } from "@langchain/core/embeddings";
import { runWithConcurrency } from "./concurrency.js";

export class NomicEmbeddings extends Embeddings {
  constructor(concurrency = 3) {
    super();
    this.model = "nomic-embed-text";
    this.apiUrl = "http://localhost:11434/api/embeddings";
    this.concurrency = concurrency;
  }

  async _fetchEmbedding(text) {
    const res = await fetch(this.apiUrl, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ model: this.model, prompt: text }),
    });
    const result = await res.json();
    return result.embedding;
  }

  async embedQuery(text) {
    return this._fetchEmbedding(text);
  }

  async embedDocuments(documents) {
    const results = Array.from({ length: documents.length });
    await runWithConcurrency(
      documents,
      async (text, idx) => {
        try {
          results[idx] = await this._fetchEmbedding(text);
        } catch (err) {
          results[idx] = err;
        }
      },
      this.concurrency,
    );
    return results;
  }
}
```

不想自己写池子，用 `p-limit` 限住同时进行的 Promise 个数：

```bash
pnpm add p-limit
```

```js
import pLimit from "p-limit";

const limit = pLimit(3);
const tasks = texts.map((text) => limit(() => getEmbedding(text)));
const result = await Promise.all(tasks);
```

# 向量库

`MemoryVectorStore` 把向量放在内存里，没有额外服务，适合本地把流程跑通。进程一停数据就没了。

`addDocuments` 收 `Document[]`，内部会调 `embedDocuments`。

```js
import { MemoryVectorStore } from "@langchain/classic/vectorstores/memory";

const store = new MemoryVectorStore(embeddings);
await store.addDocuments(splitterDocs);
console.log(store.memoryVectors);
```

## 检索

`store.asRetriever(2)` 就是 `store.asRetriever({ k: 2 })`：每次返回最像的 2 条。返回值是 `VectorStoreRetriever`。

```js
const retriever = store.asRetriever(2);
const res = await retriever.invoke("Agent评测思路");
```

完整配置：

```js
const retriever = store.asRetriever({
  k: 2,
  searchType: "mmr",
  searchKwargs: { fetchK: 20, lambda: 0.5 },
  filter: (doc) => doc.metadata?.source?.endsWith("data/test.txt"),
  tags: ["demo", "kong"],
  metadata: { lesson: "RAG-intro" },
  verbose: true,
});
```

- `k`：返回条数，默认 4
- `searchType`：`similarity` 只看像不像；`mmr` 在「像」和「不要都挤在同一处」之间折中
- `fetchK`：MMR 先抓多少候选。`lambda` 越接近 1 越看相关性，越接近 0 越看多样性
- `filter`：返回 `true` 的文档才参与检索
- `callbacks` / `tags` / `metadata`：挂到这次运行上，方便日志和追踪
- `verbose`：是否打印详细日志

# 检索优化

标准 RAG 是三步：先索引，再检索，最后生成。进阶做法是在检索前后再加工：把问题改写成几种问法，或把检索到的段落压短。

## MultiQueryRetriever

用模型把一个问题改写成多种说法，每种都检索一次，再合并去重。避免用户换了个说法就召不回。

`k` 是 2、`queryCount` 是 3 时，理论上最多 6 条；去重后会少一些。

```js
const r = MultiQueryRetriever.fromLLM({
  llm, // 用它来改写问题
  retriever,
  queryCount: 3,
});
const res = await r.invoke("Agent评测思路");
```

## ContextualCompressionRetriever

检索到原文之后，再让模型把和问题无关的句子拿掉。`LLMChainExtractor` 就是这种压缩器。

```js
const extractor = LLMChainExtractor.fromLLM(llm);
const docs = [
  new Document({
    pageContent: "孔乙己走到酒店，说“要一碟茴香豆”。茴香豆常作为下酒小菜。",
  }),
  new Document({
    pageContent: "另一个段落：今天的天气很好，阳光明媚。",
  }),
  new Document({
    pageContent: "游泳池边上，游过一群小黄鸭",
  }),
];
const res = await extractor.compressDocuments(docs, "茴香豆的作用");
```

## ScoreThresholdRetriever

只留下相似度不低于阈值的文档。分数不够就宁可少返回，也不把勉强相关的塞进来。

```js
const r = ScoreThresholdRetriever.fromVectorStore(store, {
  minSimilarityScore: 0.7,
});
const res = await r.invoke("茴香豆是做什么用的");
```

候选不够时它会再抓一批，直到够数或碰到上限：

- `kIncrement`：每次多抓多少，默认 10
- `maxK`：最多抓多少，默认 100
- `searchType`：同样可以改成 `mmr`
