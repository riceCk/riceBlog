# 🛟 回退机制

主链失败时，按顺序换备用链，调用方还是一次 `invoke`。可以是换一个模型，也可以是远程挂了改走本地。

`withFallbacks` 挂在任意 Runnable 上。主 Runnable 抛错，才按数组顺序试后备，直到有一个成功，或全部失败。

```js
import { RunnableWithFallbacks } from "@langchain/core/runnables";

const resilient = new RunnableWithFallbacks({
  runnable: primaryRunnable,
  fallbacks: [fallback1, fallback2],
});

// 等价写法
const resilient2 = primaryRunnable.withFallbacks([fallback1, fallback2]);
```

## 结果不达标也回退

默认只在抛异常时换链。回答里出现「抱歉」「无法」这种空话，模型并没有抛错。可以在主链末尾加一个校验：不达标就自己 `throw`，回退才会接手。

```js
import { RunnableLambda } from "@langchain/core/runnables";

const rejectIfLowQuality = new RunnableLambda({
  func: async (text) => {
    if (/抱歉|无法|我不能/.test(text)) {
      throw new Error("LowQualityOutput");
    }
    return text;
  },
});

const resilientQuality = primaryChain
  .pipe(rejectIfLowQuality)
  .withFallbacks([secondaryChain, localChain]);

const answer = await resilientQuality.invoke({
  question: "给我 3 条提升 RAG 召回质量的做法。",
});
```

# 🔔 回调机制

`invoke` / `stream` 的第二个参数是 `RunnableConfig`，用来带上下文，不是再传一份用户问题。

- `configurable`：运行时上下文，例如用户 id、会话 id
- `tags`：给这次运行打标签，方便追踪
- `metadata`：附加信息，写进日志
- `callbacks`：生命周期钩子
- `maxConcurrency`：并发上限
- `timeout`：超时

具体模型还会多出自己的参数，例如 `stop`、`tools`。

`callbacks` 是一组对象，按事件名监听：

```js
{
  callbacks: [
    {
      handleLLMStart(llm, prompts) {
        console.log("模型开始运行", prompts);
      },
      handleLLMEnd(output) {
        console.log("模型运行完成", output);
      },
      handleLLMError(error) {
        console.error("模型出错", error);
      },
      handleLLMNewToken(token) {
        console.log("新 token", token);
      },
    },
  ],
}
```

```js
const stream = await chatModel.stream("你好", {
  callbacks: [
    {
      handleLLMStart(llm, prompts) {
        console.log("模型开始运行", prompts);
      },
      handleLLMNewToken(token) {
        process.stdout.write(token);
      },
      handleLLMEnd(output) {
        console.log("模型运行完成", output);
      },
      handleLLMError(error) {
        console.error("模型出错", error);
      },
    },
  ],
});
```

`handleLLMNewToken` 每来一个片段就进一次。`handleLLMEnd` 在整段生成结束后才进，里面有 token 用量。
