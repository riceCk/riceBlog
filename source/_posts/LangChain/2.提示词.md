# ✍️ 提示词模板

模板是带空位的模具，消息是填好之后真正发给模型的成品。

```text
模板层（定义结构）  →  消息层（生成对象）  →  执行层（发给模型）
PromptTemplate         Message               model.invoke()
ChatPromptTemplate     HumanMessage / SystemMessage / AIMessage
像填空题               像填好的答卷           像交卷
```

## PromptTemplate

给补全模型用的纯文本模板。变量写在 `{花括号}` 里。结果里如果要保留花括号本身，写成 `{{` `}}`。

```js
import { PromptTemplate } from "@langchain/core/prompts";

const prompt = new PromptTemplate({
  inputVariables: ["period", "user"],
  template: "Good {period}, {user}!",
});

const result = await prompt.format({ period: "morning", user: "Alice" });
console.log(result);
```

`fromTemplate` 是同一件事的简写：

```js
const pt = PromptTemplate.fromTemplate(
  "你是一名翻译助理，请把用户输入从{input_language}翻译成{output_language}。",
);

const res = await pt.format({
  input_language: "中文",
  output_language: "英文",
});
```

## 部分填充

`partial` 先填上一部分变量，剩下的以后再补，和函数柯里化是同一个想法。变量也可以传一个函数，调用时才算值。

```js
const languageTxt = "中文";
const pt = PromptTemplate.fromTemplate(
  "你是一名翻译助理，请把用户输入从{input_language}翻译成{output_language}。回答用户：{text}",
);

const pt2 = await pt.partial({
  input_language: languageTxt,
});
const pt3 = await pt2.partial({
  output_language: "英文",
});
const result = await pt3.format({
  text: "以下内容翻译成英文：我爱你",
});
```

## 少量样本

`FewShotPromptTemplate` 先摆几条「评论 → 情感」的例子，再把用户这条接在后面。模型是在照着例子做。

```js
import { PromptTemplate, FewShotPromptTemplate } from "@langchain/core/prompts";

const examples = [
  { comment: "这个产品真不错，用的太顺手了", sentiment: "正面" },
  { comment: "服务态度很差，再也不会来了。", sentiment: "负面" },
  { comment: "质量一般，性价比不高。", sentiment: "中性" },
];

const examplePt = PromptTemplate.fromTemplate("评论：{comment} -> 情感：{sentiment}");

const pt = new FewShotPromptTemplate({
  examples,
  examplePrompt: examplePt,
  suffix: "评论：{comment} -> 情感：{sentiment}",
  inputVariables: ["comment", "sentiment"],
});

const res = await pt.format({
  comment: "外观还行，性能一般般",
  sentiment: "中性",
});
```

拼出来的样子：

```text
评论：这个产品真不错，用的太顺手了 -> 情感：正面
评论：服务态度很差，再也不会来了。 -> 情感：负面
评论：质量一般，性价比不高。 -> 情感：中性

评论：外观还行，性能一般般 -> 情感：中性
```

# 💬 Message

消息是和对话模型交互的基本单位：谁说的、说了什么，还可以带额外信息。

- `SystemMessage`：系统指令，例如「你是一名导游」
- `HumanMessage`：用户输入（也叫 user）
- `AIMessage`：模型输出（也叫 assistant）
- `ToolMessage`：工具调用的结果
- `ChatMessage`：自己指定角色名的通用消息

同样一句话，放在 `system` 里是在规定行为，放在 `user` 里只是用户说的一句。`system` 通常不会当对话原文展示，但会约束模型。

```js
import { SystemMessage, HumanMessage } from "@langchain/core/messages";

const msg = new SystemMessage("你是一位中国专业导游，请使用中文向游客介绍旅游景点");
const msg1 = new HumanMessage("你好");
```

## 成员

`content` 是正文，多数时候是字符串。多模态时改成数组，文字和图片放在一起：

```js
import { HumanMessage } from "@langchain/core/messages";

const msg = new HumanMessage({
  content: [
    { type: "text", text: "请描述这张图片" },
    { type: "image_url", image_url: "http://xxxx.png" },
  ],
});
```

另外两个字段平时知道名字即可：

- `additional_kwargs`：某个模型 API 的扩展字段
- `invalid_tool_calls`：模型想调工具，但参数解析失败、对不上标准结构

# 结构化提示词

多轮对话不要挤进一个大字符串。按角色拆开，模型更容易分清哪些是规矩、哪些是用户问题、哪些是它自己说过的话。

| 类名 | 用途 |
|:---|:---|
| `ChatPromptTemplate` | 把多条消息拼成一整段对话 |
| `SystemMessagePromptTemplate` | 系统规则，可带变量 |
| `HumanMessagePromptTemplate` | 用户这句话，可带变量 |
| `AIMessagePromptTemplate` | 预先放一条模型说过的话，用来补上下文 |

```js
import {
  SystemMessagePromptTemplate,
  HumanMessagePromptTemplate,
  ChatPromptTemplate,
} from "@langchain/core/prompts";
import { ChatOllama } from "@langchain/ollama";

function buildPrompt(sysTemplate, userTemplate) {
  const sysPt = SystemMessagePromptTemplate.fromTemplate(sysTemplate);
  const hpt = HumanMessagePromptTemplate.fromTemplate(userTemplate);
  return ChatPromptTemplate.fromMessages([sysPt, hpt]);
}

const pt = buildPrompt(
  "你是一位中国专业导游，请使用中文向游客介绍{location}的{topic}，并提供相关的历史背景和文化信息。",
  "我想问：{question}，请你用中文回答我。",
);

const res = await pt.formatMessages({
  location: "中国某些地区",
  topic: "茶叶文化",
  question: "请你介绍一下中国的茶叶文化",
});

const model = new ChatOllama({
  model: "llama3",
  temperature: 0.7,
});
const stream = await model.stream(res);
for await (const chunk of stream) {
  process.stdout.write(chunk.content);
}
```

`formatMessages` 得到的是消息数组，每一项是一轮发言：

| 字段 | 作用 |
|:---|:---|
| `SystemMessage` / `HumanMessage` | 这条话的角色 |
| `content` | 正文 |
| `additional_kwargs` | 工具调用、函数定义等附加参数 |
| `response_metadata` | 模型返回后附上的信息，例如 token 用量 |

## 组合多个提示词

变量来自好几处时，不要写进一个巨大模板。`PipelinePromptTemplate` 让每个小模板先产出一段文字，再填进最终模板。

- `pipelinePrompts`：小模板列表。每一项执行完，得到一个同名变量
- `finalPrompt`：主模板，使用这些变量拼出最终提示词

```js
import { PromptTemplate, PipelinePromptTemplate } from "@langchain/core/prompts";

const getDate = () => new Date().toLocaleDateString();

const mainPt = PromptTemplate.fromTemplate(
  `你是一个智能助理，今天{date}，主人的信息是{userInfo}，
请根据上下文完成以下任务：
{todo}`,
);

const timePt = PromptTemplate.fromTemplate("{date}，现在是{time}");
const filledTimePt = await timePt.partial({ date: getDate });
const userPt = PromptTemplate.fromTemplate("姓名：{name}，性别：{gender}");
const taskPt = PromptTemplate.fromTemplate(`
我想吃{time}的{dish}。
请再次确认我的信息：{userInfo}
`);

const finalPt = new PipelinePromptTemplate({
  pipelinePrompts: [
    { name: "date", prompt: filledTimePt },
    { name: "userInfo", prompt: userPt },
    { name: "todo", prompt: taskPt },
  ],
  finalPrompt: mainPt,
});

const result = await finalPt.format({
  time: "12:01",
  name: "张三",
  gender: "男",
  dish: "煎蛋",
});
```

每个 `pipelinePrompts` 项是一道工序，`finalPrompt` 是总装。

# 消息占位

历史对话条数不固定，不能事先写成死模板。`MessagesPlaceholder` 留一个孔，调用时把消息数组塞进去。

```js
import {
  SystemMessagePromptTemplate,
  HumanMessagePromptTemplate,
  ChatPromptTemplate,
  MessagesPlaceholder,
} from "@langchain/core/prompts";
import { HumanMessage, AIMessage } from "@langchain/core/messages";

const pt = ChatPromptTemplate.fromMessages([
  SystemMessagePromptTemplate.fromTemplate("你是一个乐于助人的AI助手"),
  new MessagesPlaceholder("history"),
  HumanMessagePromptTemplate.fromTemplate("用户问题：{input}"),
]);

const res = await pt.formatMessages({
  input: "你好",
  history: [
    new HumanMessage("今天天气怎么样"),
    new AIMessage("今天天气非常晴朗"),
  ],
});
```
