# ⚠️ Java 的异常

> 🎯 有前端经验的话，`try / catch / finally / throw` 语法本身没什么新意。这章要带走的是 Java 多出来的几条规矩：

1. **受检异常会卡编译**。`IOException`、`SQLException` 不处理，代码直接编不过。JS 没有这道门槛。
2. **业务异常往上抛，入口统一接**。方法里能补救才 `catch`；规则不满足就 `throw`。以后用 `@ControllerAdvice` 转成 `{code, msg, data}`，角色接近 axios 拦截器。
3. **NPE 是业务代码最高频的坑**。等同于 JS 的 `Cannot read properties of null`。Java 没有 `?.`，调用前要判空。
4. **收尾用 `finally`，关资源优先 `try-with-resources`**。成功、失败都要走到。

## 异常家族

```text
Throwable
├─ Error                         严重错误，业务代码不捕获
│  ├─ OutOfMemoryError           内存溢出
│  └─ StackOverflowError         栈溢出
└─ Exception
   ├─ IOException                受检：读写
   │  ├─ FileNotFoundException   文件找不到
   │  ├─ UnsupportedEncodingException
   │  └─ SocketException         连接断开
   ├─ SQLException               受检：SQL、连库失败
   ├─ ParseException             受检：日期格式（SimpleDateFormat）
   └─ RuntimeException           非受检：不强制捕获，重点
      ├─ NullPointerException              NPE，业务里踩得最多
      ├─ IllegalArgumentException          参数非法
      │  └─ NumberFormatException          数字转换失败
      ├─ IndexOutOfBoundsException         下标越界
      │  ├─ ArrayIndexOutOfBoundsException
      │  └─ StringIndexOutOfBoundsException
      ├─ ClassCastException                强转失败（多态）
      ├─ ArithmeticException               除以 0
      └─ UnsupportedOperationException     例如对不可变 List 做修改
```

Java 用异常表示错误，用 `try ... catch` 接住。异常本身是类，根是 `Throwable`。

- `Error`：JVM 级故障，捕获了也救不回来
- `Exception`：程序可以处理的错误
- `RuntimeException` 及其子类：**非受检**，编译器不强迫处理
- 其余 `Exception`：**受检**，必须 `catch`，或者在方法上 `throws`

# 捕获异常

可以写多个 `catch`，每个接住对应异常**及其子类**。子类要写在父类前面，否则编译报「已被捕获」。

```java
public static void main(String[] args) {
  try {
    process1();
    process2();
    process3();
  } catch (NumberFormatException e) {
    System.out.println(e);
  } catch (IOException e) {
    System.out.println(e);
  }
}
```

> 💡 `System.out.println(e)` 只有类型和 message 一行。要看调用栈，用 `e.printStackTrace()`，或交给下面的日志。空的 `catch` 会把错误吞掉，业务代码里别这么写。

## finally 语句

无论 `try` 是否抛异常，`finally` 里的收尾都会执行。重复写在每个 `catch` 末尾的代码，收进这里：

```java
public static void main(String[] args) {
  try {
    process1();
    process2();
    process3();
  } catch (UnsupportedEncodingException e) {
    System.out.println("Bad encoding");
  } catch (IOException e) {
    System.out.println("IO error");
  } finally {
    System.out.println("END");
  }
}
```

`finally` 里别写 `return`，它会盖住 `try` 里真正要返回的值，也可能把异常吞掉。

## 捕获多种异常

互不继承的异常，可以写在同一个 `catch` 里。有父子关系的不行，还是拆开、子类在前。兜底的 `Exception` 放最后。

```java
public static void main(String[] args) {
  try {
    process1();
    process2();
    process3();
  } catch (IOException | NumberFormatException e) {
    System.out.println("Bad input");
  } catch (Exception e) {
    System.out.println("Unknown error");
  }
}
```

## try-with-resources

要关闭的流、连接，放进 `try (...)`。离开这个块时会自动 `close`，中途抛异常也会关。比在 `finally` 里手写 `close` 少漏。

```java
try (InputStream input = new FileInputStream("a.txt")) {
  // 读取
}
```

括号里的对象要实现 `AutoCloseable`。文件、JDBC、`Scanner` 都满足。

# 抛出异常

两个关键字：

| 关键字   | 位置     | 作用                                       |
| -------- | -------- | ------------------------------------------ |
| `throw`  | 方法体内 | 立刻抛出一个异常对象                       |
| `throws` | 方法签名 | 声明「我可能抛出这个受检异常」，交给调用方 |

```java
public static int parseInt(String s, int radix) throws NumberFormatException {
  if (s == null) {
    throw new NumberFormatException("null");
  }
  // ...
}
```

`NumberFormatException` 是运行时异常，这里的 `throws` 写不写都能编译。换成 `IOException` 就不行：调用方必须 `catch`，或者继续往上 `throws`。

# 自定义异常

业务异常继承 `RuntimeException`（或再抽一层 `BaseException`）。这样 Service 不用逐个方法写 `throws`，最后交给全局异常处理。

```java
public class BaseException extends RuntimeException {
  public BaseException() {
    super();
  }
  public BaseException(String message) {
    super(message);
  }
  public BaseException(String message, Throwable cause) {
    super(message, cause);
  }
  public BaseException(Throwable cause) {
    super(cause);
  }
}
```

四个构造方法是在对齐 `RuntimeException`：平时用带 `message` 的；要把原始异常留在栈里，用带 `cause` 的。

**从 `BaseException` 派生：**

```java
public class LoginFailedException extends BaseException {
  public LoginFailedException() {
    super();
  }
  public LoginFailedException(String message) {
    super(message);
  }
  public LoginFailedException(String message, Throwable cause) {
    super(message, cause);
  }
  public LoginFailedException(Throwable cause) {
    super(cause);
  }
}

public class UserNotFoundException extends BaseException {
  public UserNotFoundException() {
    super();
  }
  public UserNotFoundException(String message) {
    super(message);
  }
  public UserNotFoundException(String message, Throwable cause) {
    super(message, cause);
  }
  public UserNotFoundException(Throwable cause) {
    super(cause);
  }
}
```

受检异常进了业务层，把它包成自己的运行时异常再抛出去，原始原因放进 `cause`：

```java
try {
  // 查库
} catch (SQLException e) {
  throw new BaseException("查询工单失败", e);
}
```

> 📌 异常用来报告「这条已经做不下去了」。正常的 if / else 分支仍然用 if，不要拿抛异常当流程控制。

# NullPointerException

对象是 `null` 时，调用它的方法或字段，就会抛 NPE。

```java
public class Main {
  public static void main(String[] args) {
    String s = null;
    System.out.println(s.toLowerCase());
    // NullPointerException: Cannot invoke "String.toLowerCase()" because "<local1>" is null
  }
}
```

## 定位 NPE

链式调用时，看报错里的 `because "... is null"`，能直接指出是哪一截为 `null`：

```java
public class Main {
  public static void main(String[] args) {
    Person p = new Person();
    System.out.println(p.address.city.toLowerCase());
  }
}

class Person {
  String[] name = new String[2];
  Address address = new Address();
}

class Address {
  String city;
  String street;
  String zipcode;
}
// because "<local1>.address.city" is null
```

这里 `city` 没赋值。写业务时，长链 `a.b.c` 先判空再调用；明确不允许为 `null` 的参数，入口处用 `Objects.requireNonNull`。

# 使用 SLF4J 和 Logback

项目里几乎都走这套：代码只依赖 SLF4J 的 `Logger`，真正写文件的是 Logback。Spring Boot 自带，现在不用单独配。

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class Main {
  static final Logger logger = LoggerFactory.getLogger(Main.class);

  public static void main(String[] args) {
    logger.info("start");
    try {
      // ...
    } catch (Exception e) {
      // 异常对象放最后一个参数，才会打出栈
      logger.error("处理失败", e);
    }
  }
}
```

级别从低到高：`debug` → `info` → `warn` → `error`。业务代码别再用 `System.out.println` 留日志。
