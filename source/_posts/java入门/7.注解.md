# 🏷️ 使用注解

## 注解的作用

注解就是贴在类、方法、字段上的**标签**。标签自己不跑代码。谁来读、读完干什么，分三种：

**1. 编译器读的（`SOURCE`）**

编译完就扔掉，不进 `.class`。

- `@Override`：让编译器检查这是不是一次正确的覆写
- `@SuppressWarnings`：让编译器忽略此处的警告

**2. 工具读 class 文件的（`CLASS`）**

会写进 `.class`，加载进 JVM 之后内存里就没有了。底层库有时靠它在加载时改 class。一般不用自己写，也不用自己读。

**3. 运行时还能读到的（`RUNTIME`）**

加载后一直留在 JVM 里，可以用反射读出来。平时用到的注解多半是这种。例如 `@PostConstruct`：构造方法跑完后自动调用那个方法。这是某段 Java 代码读了注解再去调用的，JVM 本身不认识它。

`@Check` 只是把 `min` / `max` 记在字段上：

```java
public class Main {
    @Check(min = 0, max = 100, value = 55)
    public int n;

    @Check(value = 99)
    public int p;

    @Check(99) // 参数名叫 value 时可以省略，等价于 @Check(value = 99)
    public int x;

    @Check // 三个参数都用默认值
    public int y;
}

@interface Check {
    int min() default 0;
    int max() default 100;
    int value() default 0;
}
```

> 💡 贴上 `@Check` 不会自动检查 `n`。没有代码去读这张标签，它就只是摆在那里。

# 🧩 定义注解

用 `@interface` 声明。里面每个方法是一个参数，`default` 是不写时的默认值。

## 元注解

元注解是贴在注解上的注解，用来约束这个注解自己。

**@Target**：允许贴在源码的哪些位置。

- 类或接口：`ElementType.TYPE`
- 字段：`ElementType.FIELD`
- 方法：`ElementType.METHOD`
- 构造方法：`ElementType.CONSTRUCTOR`
- 方法参数：`ElementType.PARAMETER`

```java
@Target(ElementType.METHOD)
public @interface Report {
    int type() default 0;
    String level() default "info";
    String value() default "";
}
```

多个位置写成数组：

```java
@Target({ ElementType.METHOD, ElementType.FIELD })
public @interface Report {
    int type() default 0;
    String level() default "info";
    String value() default "";
}
```

**@Retention**：这张标签能活多久。

- `RetentionPolicy.SOURCE`：只在编译期
- `RetentionPolicy.CLASS`：只留在 class 文件里
- `RetentionPolicy.RUNTIME`：运行期还能读。自己定义、还打算用反射读的，用这个

```java
@Retention(RetentionPolicy.RUNTIME)
public @interface Report {
    int type() default 0;
    String level() default "info";
    String value() default "";
}
```

反射把值读出来：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.Method;

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@interface MyTag {
    String value();
}

public class Main {
    @MyTag("test-method")
    public void hello(String name) {
        System.out.println(name);
    }

    public static void main(String[] args) throws Exception {
        Method m = Main.class.getMethod("hello", String.class);
        if (m.isAnnotationPresent(MyTag.class)) {
            MyTag anno = m.getAnnotation(MyTag.class);
            System.out.println(anno.value()); // test-method
        }
    }
}
```

**@Repeatable**

允许同一个位置重复贴同一个注解。用得少，看到它知道「这个注解可以贴多次」即可。

# 🔍 处理注解

## 先看懂这一句

定义注解只规定标签长什么样。程序跑起来以后，标签不会自己生效。

处理注解就是两步：

1. 用反射把标签读出来
2. 自己写 `if`，决定读到之后干什么

Spring 的 `@GetMapping`、参数校验的 `@NotNull` 看起来像自动生效，是框架启动时替你做了这两步。

能被这段反射读到的，只有 `@Retention(RetentionPolicy.RUNTIME)`。`SOURCE` 编译完已经丢了；`CLASS` 虽然在 class 文件里，JVM 不会把它装进内存，`getAnnotation` 拿到的是 `null`。

## 怎么读

`Class`、`Field`、`Method`、`Constructor` 上是同一对方法：

| 方法 | 得到什么 | 什么时候用 |
|---|---|---|
| `isAnnotationPresent(Xxx.class)` | `true` / `false` | 只想知道贴了没有 |
| `getAnnotation(Xxx.class)` | 注解对象；没贴就是 `null` | 还要读 `min()`、`value()` |

要读参数，用第二种再判空就够。第一种只是少写一次空判断。

```java
// 只问有没有
Person.class.isAnnotationPresent(Report.class);

// 拿标签本体。平时用这个
Report report = Person.class.getAnnotation(Report.class);
if (report != null) {
    int type = report.type();
    String level = report.level();
}
```

上面的 `MyTag` 就是在方法上走了同一条路：`getMethod` → `getAnnotation` → `anno.value()`。

字段、构造方法只是把对象换掉：

```java
Field field = person.getClass().getField("name");
Range range = field.getAnnotation(Range.class);

Constructor<?> constructor = Person.class.getConstructor();
// constructor.getAnnotation(...)
```

## 自己写检查：@Range

想限制字符串字段的长度。`@Range` 只记下 `min` / `max`，比较长度的代码要另写。

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Range {
    int min() default 0;
    int max() default 255;
}

public class Person {
    @Range(min = 1, max = 20)
    public String name;

    @Range(max = 10)
    public String city;
}
```

`check` 每转一圈做四件事：

1. `getFields()` 拿出所有 **public** 字段（和反射一样，不含 `private`，含父类的 public）
2. `getAnnotation(Range.class)`：没贴就是 `null`，跳过
3. `field.get(person)`：拿出这个对象上该字段现在的值
4. 值是 `String` 时，用长度比 `range.min()` / `range.max()`，超出就抛异常

```java
void check(Person person) throws IllegalArgumentException, ReflectiveOperationException {
    for (Field field : person.getClass().getFields()) {
        Range range = field.getAnnotation(Range.class);
        if (range != null) {
            Object value = field.get(person);
            if (value instanceof String s) {
                if (s.length() < range.min() || s.length() > range.max()) {
                    throw new IllegalArgumentException("Invalid field: " + field.getName());
                }
            }
        }
    }
}
```

`name` 的长度超过 20 时，循环走到 `name` 会抛 `Invalid field: name`。`city` 没超过 10 就放过。没贴 `@Range` 的字段不会被检查。

这段逻辑要自己调用 `check(person)` 才会发生。`new Person()` 时 JVM 不会顺手跑它。以后 Spring 的校验，就是框架看到 `@NotNull`、`@Size` 后替你调用类似的检查。

字段若是 `private`，`getFields()` 拿不到。改成 `getDeclaredFields()`，再 `field.setAccessible(true)`，和反射里读私有字段一样。

## 方法参数上的注解

类、字段、方法本身，一张位置通常看一个注解，`getAnnotation` 就够。

参数麻烦一点：一个方法有好几个参数，每个参数上又能贴好几张注解。一次全拿出来，是一个**二维数组**。

```java
public void hello(@NotNull @Range(max = 5) String name, @NotNull String prefix) {
}
```

```text
annos[0]  →  第 1 个参数 name    →  [ @NotNull, @Range(max=5) ]
annos[1]  →  第 2 个参数 prefix  →  [ @NotNull ]
```

外层下标对得上参数顺序，从 0 开始。内层是这个参数上的每一张标签。

```java
Method m = Person.class.getMethod("hello", String.class, String.class);
Annotation[][] annos = m.getParameterAnnotations();

for (Annotation anno : annos[0]) { // 只看 name 上的注解
    if (anno instanceof Range r) {
        r.max(); // 5
    }
    if (anno instanceof NotNull) {
        // 贴了 @NotNull。它没有参数，确认有这张标签即可
    }
}
```

数组里的元素类型只是 `Annotation`，看不出是 `@Range` 还是 `@NotNull`，所以用 `instanceof` 认一下，才能调用 `max()`。

业务代码很少手写这段。记住「参数注解是二维数组，外层下标就是参数顺序」。校验框架内部就是这样读的。
